## 1. Tech stack and constraints

- **Plain static site**: hand-written `index.html`, `styles.css`, `main.js`. No React, no Tailwind, no Bootstrap.
- **No build tooling.** Files must work by opening `index.html` directly.
- Hosting: **GitHub Pages**, served from the repo root of `https://github.com/TahaTvln01/TURME_website`.
  - Final URL will be `https://tahatvln01.github.io/TURME_website/` (a *project page*, i.e. served from a sub-path).
  - Therefore: **all asset and link paths must be relative** (`assets/img/x.png`, `#team`), never root-absolute (`/assets/...`).
  - Add an empty **`.nojekyll`** file at the repo root so GitHub Pages serves the files as-is.
- Only external dependency allowed: **Google Fonts** via `<link>`. Nothing else.
- JS must be minimal (a few dozen lines), vanilla, no libraries. The site must remain fully readable and
  navigable with JS disabled.
- Must be fully responsive from **320px** up. Test mentally at 320 / 375 / 768 / 1440.
- Accessibility floor: semantic landmarks (`header/nav/main/section/footer`), one `<h1>`, logical heading order,
  visible `:focus-visible` styles, `alt` on every image, colour contrast ≥ 4.5:1 for body text,
  and `@media (prefers-reduced-motion: reduce)` disabling all motion.

## 3. Design direction (follow this exactly — do not substitute your own defaults)

The subject is an engineering capstone: specification documents, architecture diagrams, UI wireframes.
The aesthetic is **technical-document precision**, not startup-landing-page.

**Do not** produce: cream background + big serif + terracotta accent; near-black + acid-green accent;
generic gradient hero; card grid with drop shadows everywhere. Those are the tells of a templated build.

**Tokens** (define as CSS custom properties on `:root` and derive everything from them):

```
--ink:        #101820   /* primary text */
--ink-soft:   #5C6660   /* secondary text */
--paper:      #F4F5F3   /* page background */
--surface:    #FFFFFF   /* cards, panels */
--line:       #D8DBD6   /* hairline rules and borders */
--accent:     #1F6F5C   /* pine green — links, active states, the one saturated colour */
--accent-soft:#CFE3DA   /* accent tint for chips/highlights */
```

**Type** (Google Fonts):
- Display: **Space Grotesk** (600/700) — project name, section headings.
- Body: **IBM Plex Sans** (400/500) — all prose.
- Utility: **IBM Plex Mono** (500, uppercase, `letter-spacing: .08em`, small) — section eyebrows,
  labels, table headers, TBD chips, footer meta.

Type scale: 3.5rem / 2rem / 1.375rem / 1rem / .8125rem, tightened line-height on display
(1.05) and comfortable on body (1.6). Clamp the display size for mobile.

**Layout**: single column, max content width 1080px, generous vertical rhythm (section padding
`clamp(4rem, 9vw, 7rem)`), sections separated by 1px `--line` rules rather than alternating background
blocks. Border-radius: 4px, used sparingly. Shadows: none — depth comes from hairlines and spacing.

**Signature element (the one memorable thing):** TURME is an acronym of the five members' initials.
In the hero, set **TURME** as five large individual letters in the display face, each an anchor to that
member's card in the Team section. On hover/focus, the letter fills with `--accent` and its member's name
appears beneath it in the mono face (placeholder name for now). On mobile the letters shrink and the name
line sits under the whole wordmark. This is the only place motion is used, apart from a subtle
underline transition on links. Keep everything else quiet.

## 5. Placeholder convention (important)

Every piece of content the team still has to supply must be:
1. Wrapped in a visible, tasteful marker — a small mono chip `<span class="tbd">TBD</span>` — so a grader
   reads it as "intentionally pending", not as broken. Do **not** use lorem ipsum.
2. Preceded by an HTML comment in the form `<!-- TODO(content): <what to put here> -->`.
3. For links, additionally carry a `data-todo="<key>"` attribute.

Use exactly the string `TODO(content)` everywhere so the team can find all of them with one search.
Placeholder prose must be short, neutral English — e.g. "A one-sentence summary of the project will
appear here." Never invent fake project details, fake names, fake bios or fake report dates.
